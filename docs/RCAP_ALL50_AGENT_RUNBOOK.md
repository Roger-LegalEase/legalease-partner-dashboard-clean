# RCAP All-50 Agent Runbook

## Scope

Finish the existing full-product scope: all 51 jurisdictions, all 346 existing families and applicable consumer, sponsored and Clinic-assisted paths. Required Expungement.ai UI and secure save/claim/return, assembly, funding, privacy and delivery connections are in scope. Follow current AGENTS.md, the Product Contract and later target-specific owner amendments.

## Default Workflow

1. Read current source, assignment, runtime and accepted evidence; snapshots are dated.
2. Use the existing family register. Name the exact prior implementation/assets,
   first missing connection or demonstrated defect, one writer and observable result.
3. Reuse accepted code, forms, maps and decisions. Fix shared registration,
   specification, assembly and asset packaging once. Ingest/build only a genuinely
   missing or changed input; never restart all-state loops for a handoff.
4. Implement the smallest complete change, including affected callers and tests.
   Source acceptance, integration, deployment and customer verification remain separate.
5. Test only the affected behavior and applicable existing release gates. Use independent
   required components/form revisions, saved facts and procedural stages as expectations.
6. Integrate through Root, qualify the actual app/service/worker/assets/DB/config tuple,
   and execute the required customer delivery and authorization checks through V1.
7. Use existing reviewed publication and rollback procedures under recorded authority.
   Commit only named owned paths; never use blanket staging.

## Nationwide Ingestion Rules

Reuse `private/Nationwide Record Clearing/` and the existing recovered Master Library/custody receipts as the source inventory. An absent normal path does not prove the source is globally absent. Do not redownload or recopy the corpus.

Use `private/Nationwide Record Clearing/` as the original source inventory. Normalize state names and common folder misspellings. Every state plus DC must have an entry. If a resource is missing, mark it explicitly and keep building.

Do not block ingestion on visual review, counsel review, source freshness review, or Roger approval.

## State Build Rules

Each state should receive:

- source inventory
- build status
- review status fields
- loop history
- strategy candidates
- output artifact paths
- missing resource notes where needed

Build status can advance to `state_built` before visual/counsel/source review. Review statuses carry those pending states separately.

## Official PDF Overlay Factory

For states with official PDFs:

- classify PDFs where possible
- draft field-map candidates
- render overlay samples where feasible
- record failures as retry items
- generate visual review artifacts

Visual approval is not required to create draft maps, samples, manifests, or review packets. Visual approval is required only before `approved_for_live` or `live`.

## Field-Map Retry Loop

Retry field mapping using conservative signals:

- AcroForm field names
- widget rectangles
- known state-pack required fields
- form title and form number
- nearby text where available
- manual placeholder targets when no safe match exists

Each retry should preserve uncertainty instead of inventing semantic certainty.

## Custom Pleading Factory

For pleading states/tracks, draft packets from Nationwide references and coded state-pack materials. Use state-specific relief vocabulary. Keep missing data explicit. Do not represent drafts as attorney-approved.

## Guidance Packet Fallback

Draft guidance may support internal review and QA planning. It never substitutes for a required substantive customer packet. Preserve existing approved guidance/no-filing/held treatments; do not downgrade required packets to make completion counts pass.

Guidance packets should include:

- relief vocabulary
- source inventory summary
- likely filing path or agency path where known
- missing-data list
- safe disclaimers
- review checklist

## Packet Render QA Loop

Use the existing focused tests and accepted output evidence. Verify the actual
route/family/specification, required runtime asset identity/revision, protected
saved-fact mapping, stage and independently required document components. Inspect
changed generated and downloaded output for field placement, text fit, protected
signature/notary/agency/judicial blanks and instructions. A PDF header, page count,
successful job/upload or checklist naming the forms does not establish inclusion.
Add targeted missing/wrong component, asset and stage refusals through the real
shared path. Approved custom pleadings and guidance remain valid for their exact
treatments; external certificates stay genuine external prerequisites.

Reuse shared substantive coverage where applicable; separately qualify actual
consumer/sponsored/Clinic ownership, consent, funding and stage differences.
Preserve the same owned matter, payment history and prior artifacts on correction.
Do not rerender unchanged accepted families or the erased Mississippi matter.

## Review Artifact Loop

Generate post-build review packets for:

- attorney/counsel review
- visual overlay review
- source inventory review
- build QA
- internal preview QA

Reuse accepted artifacts by their relevant source/configuration/input bindings. Generate a successor only for a changed input, demonstrated failure or uncovered requirement; preserve the original and correction in separate exclusive run locations.

## Internal Preview Loop

Internal previews are allowed. Do not expose unapproved new-engine output to live users. Live routing follows the existing target-specific authorization and applicable verification; do not request a duplicate generic approval.

## Worktree Separation

Stay in this worktree. Do not edit another agent's active worktree. Avoid concurrent edits to the same manifest/scripts. If another agent has active unmerged changes in a shared file, coordinate through the user or commit boundaries.

## Approval Gates

Check existing authorization for the actual target before production/main, SQL/auth/RLS, live money, environment, destructive or other-worktree actions. Ask only for an exact action genuinely outside existing grants. Later owner domain/sequence exceptions remain controlling.
