# Terminalization provenance re-review queue

Generated by `scripts/terminalization/generate-provenance-review-queue.mjs` from `data/rcap-all50/terminalization-provenance-supersessions.json`. Do not edit by hand — edit the record and regenerate.

## Why this queue exists

Every unit below is a terminalization review that was performed against compiled-profile bytes the repository no longer has. Lane C1 and lane C2 refuse each of them until the review named here exists and binds the exact digests named here. That refusal is deliberate and it is safe to hold: no route in this queue carries commercial authority, so nothing here is sold, checkout-enabled, sponsored or credit-consuming while the reviews are outstanding.

## The rule that sets each scope

Before this mechanism existed, provenance digests were moved in place — 25 events across four commits in August 2026, none of which moved a `reviewedAsOf` date with it. So for many units the digest a record pins is **not** the digest its review saw. Where that is the case the review baseline is forced back to the digest the record was first committed with, and where a unit has more than one such original, to the widest of them. Reviewing from the pinned digest instead would re-review the later half of the change and leave the earlier half carrying a review nobody performed.

## How a unit leaves this queue

A reviewer produces a record, and the unit's `disposition.reviewRecord` is set to:

```json
{ "path": "<the review document>", "sha256": "<its digest>",
  "bindsBaselineSha256": "<the baseline below>", "bindsCurrentSha256": "<the current digest below>" }
```

Both bindings are checked. A review record that does not name both ends is a document about some other pair of digests, and is refused. Nothing in this repository can write a `reviewRecord` on a reviewer's behalf.
